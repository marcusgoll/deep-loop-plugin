# Lens: visual

Compares two rendered interface screenshots.

## Dimensions

Four, not six. Colour and typography are deliberately excluded — see below.

| Dimension | The question | Signals |
|---|---|---|
| **hierarchy** | Where does the eye land first, and is that the right thing? | primary action prominence, heading weight vs. body, competing emphasis, grouping |
| **spacing & rhythm** | Is vertical rhythm consistent and are related things visibly related? | gutter consistency, alignment to a grid, cramped or floating regions, optical balance |
| **states** | Is the focused element's condition legible? | focus ring presence, contrast and offset; disabled and error treatment *where already rendered* |
| **density** | Is information-per-screen appropriate for the task? | content vs. chrome ratio, scroll required to reach the primary action, whitespace that reads as unfinished rather than deliberate |

## Excluded, on purpose

**Colour** — `.claude/hooks/design-token-validator.sh` already runs on every edit and
deterministically rejects hardcoded hex, `rgb()`/`hsl()` functions, arbitrary Tailwind
values, palette colour classes, and dark-mode bypasses. A model eyeballing two PNGs is
strictly worse than that grep, and adding it here would produce findings that contradict
a hook the codebase already enforces.

**Typography** — `DESIGN.md` and `tokens.json` are authoritative, not the prototypes.
The auth prototypes load DM Sans via Google Fonts while the app correctly ships Geist.
A critic scoring typography against those prototypes would report a font divergence on
every route and drive FIX to regress the app away from its own design system. If the
prototypes are ever brought back in line, revisit — but the token files should stay
authoritative regardless.

The general rule: **the reference owns what a validator cannot express.** Layout
hierarchy, rhythm, state coverage and density have no linter. That gap is this lens.

### What `states` does *not* cover

Hover, loading and toast states never appear in a static render, so the critic cannot
judge them and must not be asked to. Focus is covered only because capture explicitly
focuses the first input before shooting — without that step `states` would be
unobservable and any finding on it would be invention. This was caught by the
`focus-stripped` fixture producing byte-identical images on its first run.

Widening this dimension means adding interaction steps to capture, not editing this
table.

## Capture

Both sides shot by `apps/web/e2e/critic/capture.critic.spec.ts` at identical viewport
with animations disabled, reusing `e2e/visual/helpers/stabilize.ts`. Full-page, so
density and scroll-depth differences are visible rather than cropped away. The first
input is focused on both sides so focus treatment is present in the pixels; a focus
ring does not shift layout, so the other three dimensions are unaffected.

Prototypes pull `cdn.tailwindcss.com` and Google Fonts at render time, so capture needs
network and is not fully deterministic. Acceptable for a pilot; vendor the assets if
this lens becomes routine.

## Calibration fixtures

Known-answer cases, generated by CSS-injecting degradations into the *reference* render
via Playwright `addStyleTag` — so both sides of a fixture come from the same source and
the only variable is the injected defect.

| Fixture | Input | Required verdict | Catches |
|---|---|---|---|
| `identical` | reference vs. itself | `tie`, scores within 0.3 | Inventing faults on demand. **Hard fail — blocks the pilot.** |
| `focus-stripped` | `*:focus{outline:none!important;box-shadow:none!important}` | reject, dimension `states` | Whether dimensions discriminate or just sound plausible |
| `rhythm-broken` | `+8px` on section gutters | reject, dimension `spacing` | Same, for the subtlest real dimension |
| `order-flipped` | any pair, A/B swapped | verdict identical to unflipped | **Position bias** |
| `unrelated` | reference vs. a different page | hard reject | Floor sanity |

### On the order-flip test

Pairwise LLM judging has a documented tendency to favour whichever option appears first.
Capture already re-flips per round, but randomising an unmeasured bias converts a
systematic error into flaky verdicts — worse, because it looks like model noise. This
fixture measures whether randomisation is sufficient. If verdicts disagree on flip,
every real verdict must be run both ways and counted only on agreement.

### Detection floor: ≤2px

`rhythm-broken` adds a delta to each element's computed margin (a DOM pass, not a
stylesheet — CSS cannot reference an element's own computed value). Swept at +2/4/8/16px,
all four were caught and attributed to `spacing` with blocking severity. The floor is at
or below 2px and is not yet bounded from below.

So a `spacing` finding is trustworthy, and the *absence* of one is real evidence rather
than a shrug.

## Calibration results

Round 1: 8/8 pass. The `identical` gate held (tie, equal scores, every finding
attributed to both sides). No position bias — the flipped fixture inverted its verdict
with the defect. Dimension attribution was correct on every degradation, and no agent
strayed into colour or typography.

One caveat that affects the mechanism: **the undegraded side scored 6 in seven of eight
fixtures.** Separation from a degraded side is healthy, but the clean baseline barely
moves. This confirms gating on A/B rather than a score threshold, and it means the
plateau guard will tend to exit early — a genuinely improved candidate may still score
6 and read as plateaued. Safe direction, but revisit the 0.3 threshold once the pilot
produces round-over-round data.
