# Design Grill integration

Deep Loop owns scope, planning, recovery, acceptance, and delivery. Design Grill resolves design intent and establishes an approved brief. Product Design and the selected design specialists retain creative work and their approval gates.

## Select the intake path

Use the installed `design-grill` skill when material design intent is unresolved, or when the user explicitly requests it. Resolve its entrypoint from the supplied path or current catalog. Read that entrypoint and its referenced shared contracts. If the required skill is unavailable, report the missing dependency and continue independent work; do not silently substitute grouped native intake.

A specified edit with sufficient approved direction uses the existing Deep Loop path. Do not require a new interview for a typo, an established component fix, or an already approved design brief. Reopen only decisions affected by new evidence or a scope change. Non-design intent uses native Deep Loop intake.

## Run one design interview

Inspect supplied facts, existing project materials, and the locked decision ledger first. Research discoverable facts. Keep one dependency-aware decision tree in the existing brief or decision map; do not create a second authority.

Ask exactly one frontier decision per turn, with a recommended answer, alternatives, and the main tradeoff. Then stop the interview turn and wait for the answer. Do not queue another design question through an asynchronous tool while that question remains open. Independent research and authorized work may continue. Recommendations, preselected options, silence, and timeouts are not answers.

After each answer, record its owner and evidence, distinguish proposals from approved decisions, and recalculate dependencies. Never re-ask a settled decision. Raise contradictions with locked decisions before dependent work.

Use Design Grill's coverage and progressive fidelity: content inventory → information architecture → journey → representative structure → design directions. Resolve the material needs for audience, context, medium, actual content, jobs, entry/exit flows, recovery, design system, constraints, research, accessibility, geometry, assets/licensing, risks, representative screens, and acceptance evidence. Use existing facts to fill known items rather than turning this coverage into a fixed questionnaire.

## Approve and hand off

Finish the interview only when no material decision blocks reliable ideation, assumptions have an owner or a test, and the brief states how to prove success. Present a compact summary and obtain explicit shared-understanding approval before invoking new creation stages. An empty frontier or a completed checkpoint is not approval. Reuse an attributable existing brief approval when its scope is unchanged.

Retain the shared stage contract in the existing design authority: identity/version, stage/status, input/output references, locked decisions and owners, assumptions, authorization evidence, provenance, acceptance scenarios/results/evidence, and next stage. Missing values remain unknown. Link this authority from `plan.md` when checkpointing; no checkpoint schema change is required.

Each implementation recommendation uses these exact fields in order:

- **Question:** One falsifiable user or problem outcome.
- **Build:** The bounded change and affected surfaces or components.
- **Why:** The consequence of leaving the problem unresolved.
- **Prove:** A reproducible check that answers Question, including a failure case and required evidence.

Carry the approved brief, decision ledger, open assumptions, and these recommendations into Deep Loop PLAN. Brief approval does not approve a visual target, authorize source changes outside the task, or establish acceptance. For UI work, continue through the [UI adapter](ui-ux-integration.md), including Product Design alternatives, owner selection, contract binding, rendered checks, and endpoint readback where required. Apply the selected medium's specialist checks for other design work. Planning-only work ends with the approved brief and verified handoff.

On resume, recover the same brief, approval evidence, locked decisions, and any pending question. Resume at the next unresolved frontier; do not restart the interview or infer approval from “continue.”
